Preliminary Phase: Architecture Capability

Core Value Proposition

Defines the "where, what, why, who, and how" of Enterprise Architecture[cite: 2].

💡
Must-Know Foundation Fact: The Preliminary Phase is the foundational preparation phase executed before initiating formal ADM cycles (Phases A through H)[cite: 1, 2]. Its main goal is to create and enable the enterprise's Architecture Capability[cite: 1, 2].

Primary Purpose

Prepare the enterprise for successful architecture work[cite: 2]. This includes customizing the TOGAF framework[cite: 1, 2], establishing the organizational model and governance structures[cite: 1, 2], and defining enduring Architecture Principles[cite: 1, 2].

Establishes operational capability before Phase A[cite: 1, 2].

The 5 Core Architectural Questions (Approach)[cite: 2]

1. Where

Define the enterprise scope & impacted organizational boundaries[cite: 1, 2].

2. Why

Identify key drivers, business imperatives & strategic context[cite: 1, 2].

3. What

Set requirements & desired architecture capability scope[cite: 1, 2].

4. Who

Establish the EA Team, roles, & Organizational Model[cite: 1, 2].

5. How

Formulate Architecture Principles, Governance framework, & tooling strategy[cite: 1, 2].

Detailed Phase Objectives[cite: 1, 2]

Objective Focus Key Activities Target Deliverable / Outcome
Capability Maturity Target Review organizational context; determine desired EA maturity level[cite: 1, 2]. Capability Maturity Baseline & Target Assessment[cite: 1, 2].
Framework Customization Tailor the TOGAF ADM, deliverables, tools, and terminology[cite: 1, 2]. Tailored Architecture Framework[cite: 1, 2].
Governance & Organization Define EA team roles, reporting lines, and Architecture Board[cite: 1, 2]. Organizational Model for EA & Governance Framework[cite: 1, 2].
Architecture Principles Establish enduring guidelines for Business, Data, App, & Tech[cite: 1, 2]. Architecture Principles Catalog[cite: 1, 2].
Tooling & Repository Select modeling tools and set up the Architecture Repository[cite: 1, 2]. Configured Architecture Repository & Tools[cite: 1, 2].
⚠️
Exam Pitfall: Do not confuse Architecture Principles (defined in the Preliminary Phase)[cite: 1, 2] with Business Principles (which are confirmed/elaborated in Phase A)[cite: 1]. Principles defined here guide all downstream target architecture decisions[cite: 1, 2]!

Step 1: Scope the Enterprise Organizations Impacted[cite: 1, 2]

Identify core business units, departments, strategic partners, and external ecosystems affected by the Architecture Capability[cite: 1, 2].

Key Activities: Identify organizational boundaries, evaluate enterprise breadth, determine impact on strategic plans[cite: 1, 2].

🎯 Exam Note: Enterprise scope can range from the entire enterprise down to a specific business unit or segment[cite: 1].

Step 2: Confirm Governance and Support Frameworks[cite: 1, 2]

Review and align intersecting management frameworks operating in the enterprise (e.g., ITIL, COBIT, PRINCE2, SAFe)[cite: 1, 2].

Key Activities: Map EA touchpoints with project management, operations, and strategic planning processes[cite: 1, 2].

🎯 Exam Note: TOGAF ADM can be tailored to complement and integrate with non-TOGAF frameworks[cite: 1].

Step 3: Define and Establish EA Team and Organization[cite: 1, 2]

Formalize the EA team structure, define architect roles/skills, and establish the Architecture Board[cite: 1, 2].

Key Activities: Assign responsibilities, define skill profiles, and establish C-level reporting lines[cite: 1, 2].

🎯 Exam Note: The Organizational Model for EA specifies where EA fits within corporate hierarchy[cite: 1, 2].

Step 4: Identify and Establish Architecture Principles[cite: 1, 2]

Develop enduring general rules and guidelines across Business, Data, Application, and Technology domains[cite: 1, 2].

Key Activities: Formulate principles using the 4-part structure (Name, Statement, Rationale, Implications)[cite: 1].

🎯 Exam Note: Must meet 5 criteria: Complete, Consistent, Stable, Understandable, Robust[cite: 1].

Step 5: Tailor the TOGAF Framework and Others[cite: 1, 2]

Customize TOGAF Fundamental Content, ADM phases, deliverables, and terminology to fit organizational needs[cite: 1, 2].

Key Activities: Incorporate TOGAF Series Guides (e.g., Security, Agile, Digital) and establish terminology[cite: 1].

🎯 Exam Note: Customization creates the "Tailored Architecture Framework" deliverable[cite: 1, 2].

Step 6: Develop Strategy & Implementation Plan for Tools[cite: 1, 2]

Select EA software tools, configure the Architecture Repository, and issue the Request for Architecture Work[cite: 1, 2].

Key Activities: Set up repository structures, implement modeling tools, and issue the initiating document[cite: 1, 2].

🎯 Exam Note: Generates the "Request for Architecture Work", which triggers Phase A[cite: 1, 2].

Phase Inputs[cite: 1, 2]

Mandatory Strategic Context Inputs[cite: 1, 2]:
  • Organizational context, strategic plans, and business goals[cite: 1, 2].
  • Sponsorship details, corporate mission statements, and budgets[cite: 1, 2].
  • Descriptions of existing enterprise / IT systems[cite: 1, 2].
Framework & Governance Inputs[cite: 1, 2]:
  • Existing management frameworks (ITIL, COBIT, PRINCE2)[cite: 1, 2].
  • Enterprise Continuum & Standards Library assets[cite: 1].

Industry Case Study: Global Bank Digital Transformation

Executing the Preliminary Phase for a Tier-1 Financial Institution

Problem

A retail bank with operations in 10 countries suffered from duplicated IT spend, conflicting local architecture frameworks, lack of central governance, and recurring GDPR compliance risks.

EA Application

Executed Preliminary Phase: Scoped global divisions, tailored TOGAF 10 with SAFe & ITIL[cite: 1, 2], established an Architecture Board chaired by the CTO[cite: 1], and published 8 core Architecture Principles[cite: 1, 2].

Results & Outputs

Generated approved **Request for Architecture Work**[cite: 1, 2], set up a unified Architecture Repository[cite: 1, 2], reduced software duplication by 30%, and achieved 100% regulatory compliance review pass rate.

Key Execution Takeaways from the Case Study

Maturity Target Setup:

Defined a 2-year Capability Maturity roadmap from Level 1 (Ad Hoc) to Level 3 (Defined Capability)[cite: 1, 2].

Tooling Strategy:

Selected an ArchiMate-compliant modeling software integrated into ServiceNow for live application landscape views[cite: 1, 2].

🎯
High-Yield Exam Focus: The Preliminary Phase generates the Request for Architecture Work[cite: 1, 2]. It does NOT generate the Statement of Architecture Work or the Architecture Vision (both are produced in Phase A)[cite: 1].

Key Mnemonics & High-Yield Rules

Mnemonic: NSRI (Architecture Principle Template)[cite: 1] Every principle template MUST contain: Name, Statement, Rationale, Implications[cite: 1].
Mnemonic: 5 Criteria for Good Principles[cite: 1] C-C-S-U-R: Complete, Consistent, Stable, Understandable, Robust[cite: 1].
Mnemonic: 5 Core Questions[cite: 2] Where, Why, What, Who, How (Enterprise scope, Context, Requirements, Team, Principles/Governance)[cite: 2].

TOGAF 10th Edition Key Terminology Callouts[cite: 1]

Modular Structure[cite: 1]: TOGAF 10 replaces monolithic manuals with two parts: TOGAF Fundamental Content (Core concepts & ADM) and TOGAF Series Guides (Practical guidance for Agile, Digital, Security)[cite: 1].
Agile & Digital Alignment[cite: 1]: Preliminary phase explicitly guides tailoring the ADM to work concurrently with Agile team iterations and digital transformation initiatives[cite: 1].
